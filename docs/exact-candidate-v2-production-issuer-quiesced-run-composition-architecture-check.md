## Private ownership and exact state machine

One unexported, session-owned execution/terminal owner is required. Its constructor, maps, phase capabilities,
and retained references remain private; public values are frozen opaque facades. It accepts no raw DB/path,
approval, runtime, output, process, listener, proof factory, injected `verified` callback, or arbitrary
`implementationKind: 'production'` input.

The owner atomically consumes one exact active V2 seal and creates one run only:

```text
idle
  -> reserved
  -> revalidated
  -> audit-start-durable
  -> broker-arm-committed
  -> spawn-attempted
  -> running
  -> quiescing
  -> quiesced
  -> post-state
  -> compiled
  -> output-reserved
  -> output-written
  -> cleanup
  -> terminal-attempted
  -> reconciled
```

A failure latches `stopping`; it cannot select a second path, queue, retry, mint another phase handle, or resume a
forward phase. Every opaque handle binds original action/approval/session IDs, Plan3/Projection3/Envelope2,
snapshot/runtime/workspace/launch/environment/route, audit/output identity, and absolute deadlines. Copies,
foreign values, replay, downgrade, V1 inputs, synthetic-to-production promotion, revocation, deadline equality,
NaN, and backwards time fail closed.

## V2 leaseVersion2 and durable intent ordering

A private V2 lease protocol is required, not a V1 adaptation:

1. Reserve the seal and phase before awaited work.
2. Record `markExecutionStarted()` exactly once per run, before the first broker arm, DNS, or child effect. It is
   durable dispatch authority only, never proof that npm or a child started.
3. Persist each broker request intent before its DNS/HTTPS operation and the separate spawn intent before spawn.
4. Keep pending-arm distinct from committed-arm. Spawn follows only the same run's durable `broker_arm` record.
5. Run the final synchronous owner fence immediately before an effect. There is no queue, retry, or caller clock.
6. Preserve existing absolute 15-second start and 120-second execution windows. Remaining budget never resets at
   spawn; equality is expired.
7. If a start/intent append throws or commit outcome is uncertain, do no next effect, stop admission, perform at
   most one read-only reconciliation, and never retry a possibly consumed seal.

Future V2 broker/process/listener ports are version-separated and internally owned. They may reuse low-level
validation semantics but cannot accept V1 authentic handles. A proposed `graph-genesis-v2-execution.ts` module may
contain data-only state/digest/budget mechanics; it cannot mint production capability or expose a public I/O factory.

Each request ordinal/reservation is synchronously and atomically advanced before its await. Response completion is
checked against retained entries so count and byte aggregates reject concurrent lost updates. This is required even
when four responses complete in the same event-loop tick.

## Actual quiescence issuer

Only a same-run actual-quiescence predicate may produce a one-use production quiesced capability. The bound listener
must be the pre-approval session-owned capability, not a port number supplied after approval.

| Evidence | Required fact | Not sufficient |
| --- | --- | --- |
| Broker ledger | source-authenticated finalized ledger; reservation/start/commit consistency; zero active/pending transports; no unclaimed failure; disarmed | partial ledger, raw digest, a count alone, or a late unbound ledger |
| Child | spawn attempted distinct from spawn failure; observed close with completed status and exit 0 | synchronous spawn failure, close-only, `childClosed: true`, nonzero exit, output overflow, or caller boolean |
| Listener | original bound server/port shut down; handlers and sockets settled at zero; one-shot evidence bound to run | second close of no server, plain close record, delayed handler/socket, or undisposed promise |
| Failure latch | no first failure before **or after** drain | a decision made before late drain failure arrives |

Child close does not attest all descendants, the host, registry honesty, or package behavior. Existing containment
assumptions remain required. No package execution, hostile same-user quiescence, or whole-host guarantee may be
claimed.

## Revocation and bounded stopping

Cancellation, deadline, context revocation, and output revocation first disable all forward handles. The owner then
stops broker admission/aborts transports and initiates child termination plus listener shutdown concurrently.
Callbacks request/latch stop only; they do not await their own handler drain or write terminal state.

One shared stopping promise prevents reentrant deadlock and duplicate stop/cleanup/terminal work. Public close
revokes immediately, while restricted teardown and read-only-proof custody retain needed descriptor/audit
relationships until bounded stop settles. The caller-owned database is never closed or deleted by this owner.

The proposed bounds are one TERM, then one KILL after 2 seconds; child close wait no more than 4 seconds within an
absolute 5-second stop budget; listener shutdown no more than 5 seconds. These are monotonic cooperative
checks/timers, **not hard-real-time guarantees**: a stalled event loop or already in-flight kernel I/O may return
after the nominal budget. After every callback or OS-operation return, the owner rechecks fences and latches before
any additional effect or success issuance. It never writes that unobserved resources closed. An incomplete close/
drain produces bounded incomplete/unknown and preserves resources/evidence without post-state scan or deletion.

## Post-state, Artifact2, output, and cleanup

Only actual quiescence permits production post-state capture through the original owned workspace and exact Plan3
contract. Retain strict parser, bounded inventory, protected identity, runtime checks, `max + 1` reads, and
checkpoints. Existing schema2 Artifact2 binding fields remain unchanged. Broker/process/listener digests come only
from private actual issuer evidence; synthetic values remain explicit synthetic.

Revalidate post-state before output open and after write. Output needs durable intent before exclusive `0600`
no-follow creation, fsync, exact bytes/inode readback, and original output-parent binding. A written Artifact2 is
provisional, never accepted/importable/activation authority alone.

Success cleanup is possible only after quiescence plus owned post-state/inventory and exact no-follow root/entry
identity under existing budgets. One future cleanup attempt over owned entries only: no glob, recursive fallback,
or retry. Failure defaults preserve-only; quarantine requires actual secured observation. Audit/output are never
deleted. Capture exact cleanup authority before protected descriptor release; after deletion do not rescan the
removed workspace. Partial deletion preserves the remainder/incomplete and cannot succeed.

## Terminal ownership and read-only reconciliation

Exactly one terminal writer handles each post-dispatch outcome after stop settles or deadline establishes unknown.
Pre-dispatch known failure uses the existing pre-dispatch path without fabricated process facts. If an actual process
close is unobserved, orchestration is non-completed/unknown with `exitCode: null` and a closed
observation-unknown predicate; `process.failed` must not imply that a child exit was observed, and the owner must
not mint `childClosed`, `exit0`, or `cleanupComplete`. Completion requires all actual success facts, complete
cleanup, byte-verified candidate/output, and later exact read-only audit proof.

Existing `AuditCall` semantics require `terminalAudit: complete` within a completed terminal transaction; that means
atomic terminal-batch consistency, not proof already established. One owner-selected readonly/query-only reopen
then validates bounded chain, selected action, retained receipt/journal/triple, and output identity/bytes. A
returned or committed-then-thrown terminal transaction may reconcile once. A start-transaction outcome that is
uncertain allows no effects and exactly one read-only reconciliation; it never receives a fallback terminal write
that guesses dispatch state. A post-start actual failure likewise allows one terminal attempt and one reconciliation;
uncertainty never permits a second `markFailed` or other fallback terminal write. Missing/contradictory rows, DB
replacement, output drift, or reopen failure stay unknown. There is no repair, retry, import, start, or
proof-to-capability promotion.

The implemented execution tests cover durable-start-before-fake-effect ordering, original synthetic listener
identity/rebound rejection, four active transports with same-tick completion and fifth rejection/no queue, and
unobserved child-close yielding only `outcome_unknown_after_interruption` with `exitCode: null`. The remaining

arm-race rejection; cancellation/reentrancy/idle-in-flight revocation/no-forward-work/invalid-clock cases; intent

disposable `0600` SQLite/workspace/Artifact2 drift/orphan cases; one-entry cleanup failure and no rescan of an

A positive synthetic full-flow would validate only this state machine's **synthetic provenance**. Concrete
