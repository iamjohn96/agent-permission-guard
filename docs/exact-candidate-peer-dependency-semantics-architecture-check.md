## Proposed strict peer semantics v1

This is a supported subset, not full npm compatibility. Use descriptor-safe own-data dictionaries/`Map`, never prototype inheritance; reject accessors and non-data objects without needlessly forbidding a valid own package name such as `constructor`. Reject duplicate declarations, unknown fields/types, and over-budget input without truncation. `peerDependencies` is absent or name-to-bounded-string (empty allowed). `peerDependenciesMeta` is absent or keys declared in peers, with each value `{}` or exactly `{ optional: boolean }`; omitted/false is required and true optional. Preserve map presence and raw recognized declarations in identity. Reject ordinary+peer declaration of the same name; npm's edge override behavior is intentionally not emulated. Existing dev/optional/bundle/link/os/cpu/lifecycle prohibitions stay. Role flags must be absent or boolean; peer-role handling is future behavior.

Strict versions are `M.m.p` nonnegative safe integers without leading zero, `v`, coercion, prerelease, or build. Compare tuples lexicographically. Support exact (optional `=`) equality; `<`, `<=`, `>`, and `>=` tuple predicates; `~M.m.p = [M.m.p,M.(m+1).0)`; `^M.m.p` for `M>0 = [M.m.p,(M+1).0.0)`; `^0.m.p` for `m>0 = [0.m.p,0.(m+1).0)`; and `^0.0.p = [0.0.p,0.0.(p+1))`, including `^0.0.0`. AND is intersection and OR is union. A standalone `*` admits all supported stable versions. Support full-triplet `^`/`~`, ASCII-space AND, `||` OR, and standalone `*`; max 256 characters, 8 branches, 16 lexical source atoms globally, and 32 expanded primitive comparisons. ASCII space is U+0020 only: no leading/trailing whitespace, one-or-more U+0020 between AND atoms and optionally beside `||`, attached operators only (never `^ 1.2.3`), and `*` only as the entire specifier. Preserve raw specifier text even when syntax is equivalent. Reject partial/x/hyphen/tag/alias/git/file/URL/workspace/override/non-ASCII/control, empty branches, numeric overflow, and a whole specifier when any alternative is malformed—even if another alternative matches. Upper-bound increment overflow rejects and never wraps. Examples: `~1.2.3` excludes `1.3.0`; `^0.2.3` excludes `0.3.0`; `^0.0.3` excludes `0.0.4`; `>=1.0.0 <2.0.0` accepts `1.5.0` and excludes `2.0.0`. Every future peer-aware v2 resolved version and ordinary/peer specifier must pass and satisfy its first resolved target; missing optional still validates. Valid npm ranges outside this subset intentionally fail closed; do not add a dependency or full-semver clone.

## Memory-only placement, closure, and limits

Resolve only from the validated installed-path graph. Inspect declaring package `node_modules/<peer>` first: if present reject peer-local and never bypass it. Then walk enclosing structural package contexts to project top, including scoped names and parent existence; first existing target wins. Wrong version is conflict, never global/farther search. The fixed MCP top under `node_modules` is not a virtual-root exception; APG project/root is never target. Self-peer is explicitly conservative: reject when peer name equals the declaring package name, even if another installed version could resolve, and reject any resolution to the declaring node itself. Required absent rejects. Optional absent is explicit accepted absence without fetch; optional present must match closest placement/version and independently remain in required closure. Malformed/incompatible optional-present is not absence. Shared targets satisfy every constraint; scoped placements may differ. No SAT/re-resolution/overrides/legacy-peer-deps/force.

Let P be ordinary production closure from exact root; R is fixed point through ordinary plus required peer edges. Every node is in R; optional-only/unreachable rejects. In the APG restricted no-dev/no-optional/overlap subset only, normalized peer role agrees with R minus P; it is not a claim about arbitrary npm graphs with dev/optional/link/override paths, and declaration presence is not role. Ordinary edges remain acyclic across every retained node, not just P; peer constraints may host-backreference, so use bounded visited fixed point. Preserve inherited ceilings: graphNodes <=256, pathDepth <=32, relativePathBytes <=512 (`src/stage/profile.ts:13-23`); lock input <=4 MiB under existing bounded parser/plan limits (`src/stage/graph-genesis-hardening.ts:1027-1028`), honoring any lower configured limit. The pure evaluator does not read raw lock files. Cap 64 peers/node, 2048 peer requirements, and 4096 combined requirements. These ingress/enumeration/traversal guards run before costly normalization, walks, or allocation. Budget rejection wins at the encountered guard. For bounded data, diagnostics are ordered: shape; role type/prohibited role/overlap; version/specifier; ancestor resolution/missing/conflict; ordinary cycles plus P/R closure/reachability; then peer provenance. Limits fail closed without truncation, never expose counts, and do not change transport limits.
